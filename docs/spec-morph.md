# Спека 1. Таблица морфологии AOT для нормализатора

## Зачем

Нормализатор (`app/src/main/java/ru/kost/ruvoice/text/Normalizer.kt`) работает регулярками и списками, без
морфологии. Из-за этого (см. `NORMALIZER.md`): род существительного после «1/2» и порядковых на «-й/-е»
угадывается по окончанию и 400 исключениям (`SoftSignGender.kt`); падеж числительного берётся из предлога,
окончания соседнего слова и списка глаголов, но не из прилагательного перед числом («последних 20 лет»);
сокращения-прилагательные («гос. службы») не раскрываются, потому что у «службы» два разбора.

Нужна таблица «форма → возможные разборы» для существительных и прилагательных, быстрая и не влияющая
на старт приложения.

## Формат `app/src/main/assets/morph.bin`

Плоский бинарный файл, little-endian, записи по 12 байт, отсортированы по хэшу:

- 8 байт — хэш формы (64 бит, FNV-1a по UTF-8 строчной формы с «ё»→«е»; та же функция в Python и Kotlin,
  проверить тестом на трёх словах);
- 4 байта — теги.

Теги (32 бита), младшие биты первыми:

| биты | что |
|------|-----|
| 0–3 | часть речи, битами: 1 — существительное (N), 2 — прилагательное (A, ADJ_SHORT не берём), 4 — порядковое (ORD_NUM), 8 — местоимение-прилагательное (PA: «эти», «последний» в AOT — прилагательное) |
| 4–6 | род леммы: 16 — м, 32 — ж, 64 — ср (у существительных; у прилагательных не ставится) |
| 7 | 128 — одушевлённое (для существительных) |
| 8–31 | сетка число×падеж, 24 бита: биты 8–13 — ед. число, падежи nom, gen, dat, acc, ins, loc; биты 14–19 — мн. число, те же; биты 20–31 — для прилагательных: 20–25 — ед. ж. р., 26–31 — ед. ср. р. (ед. м. р. — в битах 8–13, мн. — в 14–19) |

Для существительного заполняются только 8–19; для прилагательного — 8–31 по роду формы. Объединение
разборов формы кладётся по клеткам, поэтому «службы» = {gen.sg, nom.pl, acc.pl} без ложных сочетаний.
Если одна форма — и существительное, и прилагательное (редко, «больной»), часть речи содержит оба бита,
сетка — объединение.

Берём из AOT части речи N, A, ORD_NUM, PA (в `gramtab.json` поле `p`). Ожидаемый объём: ~805 тыс. форм ≈ 9,7 МБ.
Причастия не берём. Формы с дефисом и служебные леммы (`plug_noun_gram_code`, `mas_abbr_noun` в gramtab)
пропускать. Аббревиатуры (граммема `abbr`) пропускать.

## Скрипт `tools/aot_morph.py`

Вход: каталог с `morphs.json`, `gramtab.json` (аргумент; по умолчанию scratchpad `aot/`). Логика обхода
лемм — как в `tools/aot_forms.py` (flexia_models, prefix, stem = лемма минус первая флексия; common-граммемы
леммы из `l['t']` + граммемы окончания из `gramcode`). Граммемы AOT: `mas fem neu`, `sg pl`,
`nom gen dat acc ins loc` (второй родительный/предложный — граммема `2`, класть в gen/loc), `anim inanim`.

Выход: `app/src/main/assets/morph.bin` и печать статистики (форм, байт, сколько существительных
многозначных по числу-падежу). Скрипт детерминированный: повторный запуск даёт тот же файл (проверить `cmp`).

## Kotlin: `app/src/main/java/ru/kost/ruvoice/text/Morph.kt`

```kotlin
class Morph(private val buf: ByteBuffer /* mmap ассета, order LITTLE_ENDIAN */) {
    fun tags(form: String): Int          // 0, если формы нет; бинарный поиск по хэшу
    fun isNoun(t: Int), isAdjective(t: Int), gender(t: Int): Gender?, animate(t: Int)
    fun nounCases(t: Int, plural: Boolean): Set<Case>   // Case из Declension.kt
    fun adjCases(t: Int, gender: Gender?, plural: Boolean): Set<Case>
    companion object { fun hash(form: String): Long; fun open(context: Context): Morph }
}
```

Открытие через `AssetManager.openFd("morph.bin")` → `FileChannel.map(READ_ONLY)`; ассет должен лежать
несжатым (в `app/build.gradle*` добавить `androidResources { noCompress += "bin" }` или проверить, что
`aaptOptions` уже не сжимает). Если mmap не удался (сжатый ассет, старое устройство) — фолбэк: прочитать
ассет в `ByteBuffer` целиком один раз; замерить, сколько это стоит, в логе.

В `SileroData` или рядом — ленивый синглтон на процесс, как `Prefs.audit`. Нормализатор получает `Morph?`
(null в тестах без ассета и в `Pipeline.plan` по умолчанию) — все правила должны корректно работать без него,
как сейчас.

JVM-тест `MorphTest`: собирает маленький `morph.bin` тем же алгоритмом на 5–10 формах (или читает настоящий из
`app/src/main/assets`, если файл есть — он будет в репо) и проверяет: «службы» → N, ж, {gen.sg, nom.pl,
acc.pl}; «ночь» → ж; «стол» → м, {nom.sg, acc.sg}; «последних» → A, мн. {gen, loc, acc-одуш.};
«друзьями» → ins.pl; несуществующее → 0. Замер: 100 тыс. поисков < 200 мс на JVM (печать в лог, не assert).

## Подключение в Normalizer (три отдельных коммита, каждый с тестами)

1. **Род после «1/2» и порядковых «-й/-е»** (`nomOneEndingRe`, `nomFemTwoEndingRe`, `accFemEndingRe`,
   порядковые в `daySuffix`/ordinal-логике — найти по комментарию «SoftSignGender» и «идея из ru-normalizr»):
   сначала спросить `Morph`; если форма известна и род однозначен — брать его; иначе текущая эвристика.
   Кейсы: «1 ночь → одна», «1 конь → один», «2 двери → две», «1 такси → одно» (не склон. — если в AOT нет,
   остаётся эвристика), «1 сообщение → одно», «21 минута → двадцать одна».
2. **Падеж числительного по соседнему слову**: если слово после числа — существительное с однозначным
   падежом (все клетки сетки в одном падеже, любое число), а перед числом нет предлога/глагола с
   управлением, — склонять число в этот падеж («5 друзьями» → «пятью», «7 гномам» → «семи»). Прилагательное
   или причастие перед числом с однозначным падежом («последних 20-30 лет» → «двадцати — тридцати», «первых
   5 минут» — acc/gen неоднозначно → как сейчас). Именительный/винительный — не трогать (там числительное и
   так в им. п.). Не ломать существующие правила: новые проверки — только там, где сейчас читается
   именительный «по умолчанию».
3. **Сокращения-прилагательные** (`гос.`, `полит.`, `междунар.`, `офиц.`, список из NORMALIZER.md и `Abbrev.kt`):
   раскрывать, только если существительное следом известно и его род-число-падеж однозначны (или все разборы
   дают одну форму прилагательного — «службы» gen.sg ж → «государственной», nom.pl → «государственные»:
   неоднозначно → оставить). Склонение прилагательного — по таблице окончаний (`Declension.kt` есть для
   числительных; для прилагательных добавить минимальную функцию: основа + окончание по роду/числу/падежу,
   твёрдый/мягкий вариант).

После каждого шага: `./gradlew testDebugUnitTest`, `RuNormalizrCorpusTest` не ниже 485/495 (ratchet поднять,
если выросло), diff в `app/build/ru_normalizr_diff.txt` просмотреть. NORMALIZER.md: разделы «Падеж
числительного», «Род существительного», «Сокращения-прилагательные» переписать по факту. README: пункт
про `tools/aot_morph.py` в сборке (после 2б), размер ассета, лицензия AOT уже указана.

На телефоне: `adb install -r`, `ServiceSmokeTest` и `SileroModelsTest` через `am instrument`; в логе старта
убедиться, что загрузка `morph.bin` не добавила времени (mmap) — если фолбэк на чтение целиком, сказать.
