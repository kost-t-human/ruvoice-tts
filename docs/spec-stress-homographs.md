# Спека 3. Промахи BERT на омографах → фразы и грамматика

## Зачем

155 из 309 промахов на HomographResolutionEval — омографы, где нейросеть-омосолвер (ruBERT-tiny2) выбрала
не тот вариант. Дообучения не будет (корпуса нет). Есть три рычага без обучения, все уже существуют в
конвейере `Stress.apply`: gramPass (правила по соседям, таблица `gram` в `silero_ru.json`), фразы
системного словаря замен (`tools/phrases_extra.txt` → `assets/dicts/replace/Системный.txt`), и таблица
морфологии из спеки 1 (`Morph`).

## Шаг 0. Разбор промахов

`<scratchpad>/sstress/bin/python tools/homo_eval.py` → `app/build/homo_eval_miss.txt`. Сгруппировать
промахи-омографы по слову, вывести топ-30 с долей: ожидается, что «все/всё» — до трети. Результат — в
`app/build/homo_miss_by_word.txt`, коротко в отчёт.

## Шаг 1. Контексты ё-омографов из Википедии

Пары, различающиеся только «ё» (все/всё, узнает/узнаёт, небо/нёбо, передохнуть, совершенный/совершённый,
осел/осёл…), размечены в дампе Википедии самим текстом: там «ё» пишут. Список пар — из homodict
(`silero_ru.json`: варианты, отличающиеся только «ё») плюс `eyo_not_safe.txt` (scratchpad) как проверка.

`tools/yo_contexts.py`: по дампам `ruwiki1.xml.bz2`, `ruwiki2.xml.bz2` (разбор статей — как в
`tools/wiki_yo_corpus.py`) собрать для каждой пары статистику контекстов: (слово слева, форма), (форма,
слово справа), (слева, форма, справа). Контекст — строчные слова без знаков; «ё» в самом контексте
привести к «е» (в тексте пользователя «ё» обычно нет). Кандидат во фразы — контекст с ≥ 20 вхождениями и
≥ 95 % одного варианта; из двух форм контекста (слева/справа) брать более сильную, трёхсловную — только если
двухсловные не дотягивают.

Выход: `app/build/yo_phrases.txt` в формате `phrases_extra.txt` («фраза = слов+о», для ё-варианта — с «ё»
и «+»), с комментарием «N вхождений, доля». Отфильтровать конфликт с корпусом Демагога, как делает
`phrases_extra.py` (функция `load_extra`/фильтр конфликтов — переиспользовать). Просмотр глазами
(ожидание — несколько сотен фраз), потом дописать в `tools/phrases_extra.txt` отдельной группой
`# ё-контексты из Википедии`, `python3 tools/system_dicts.py`.

Внимание: gramPass идёт раньше фраз только в Python-зеркале; в приложении замены применяются до ударений
(`Pipeline.plan`), поэтому фраза перебивает и gramPass, и BERT. Конфликты с `gram`-таблицей проверить тем же
скриптом (`gram_pick`).

## Шаг 2. Согласование с прилагательным в gramPass (после спеки 1)

Сейчас `Stress.gramPass` смотрит только на предыдущее слово (предлоги, местоимения, «-ого/-его»). С `Morph`
можно решать падежные омографы по согласованному прилагательному перед словом: «высокие стены» → мн.
(«ст+ены»), «высокой стены» → род. ед. («стен+ы»), «эти руки» → мн. Правило: предыдущее слово —
прилагательное/местоимение-прилагательное по `Morph`, и множество его (число, падеж) пересекается с
клетками омографа только в одном числе → взять вариант `p` (мн.) или `g` (род. ед.) из `gram`.
Если пересечение в обоих числах («большие» acc.pl vs …) — молчать. `Stress` получает `Morph?` через
конструктор (null — правило выключено, тесты без ассета работают).

Проверка: `GramPassCorpusTest` (ratchet MIN_FIRED/MAX_WRONG — поднять MIN_FIRED по факту), симуляция на
`ss_rows.tsv` как раньше (`tools/phrases_extra.gram_pick` — добавить зеркало правила, чтобы Python-оценка
`homo_eval.py` совпадала с Kotlin). JVM-тест в `StressTest` на 4–5 пар.

## Шаг 3. Ручные фразы по частым словам

По `homo_miss_by_word.txt` и `/home/kost/serverApp/ruvoice/homographs-unknown.txt` (там у каждого слова
фразы с ключом словаря Демагога и ответами v5/silero-stress) — для топ-20 омографов после шагов 1–2
подобрать по 3–10 фраз-подсказок в 2–3 слова из реальных контекстов (не копировать словарные строки как
есть — выбирать и сокращать до минимального контекста). «все/всё» без контекста не трогать — известная
слабость, BERT уверенно ошибается в 11 %, порог не помогает.
